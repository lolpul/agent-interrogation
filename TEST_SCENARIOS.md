# Набор ручных проверок Interrogation Mode v2

После установки запустите сценарии в Codex в отдельной копии репозитория с публичным или синтетическим примером. Используйте `/plan`, если он доступен, и запишите версию клиента и активный режим. Статусы и наблюдения внесите в [журнал испытаний](docs/MANUAL_TEST_LOG.md).

1. **Авто/Light.** `$interrogation Добавь в настройках переключатель отображения сетки.`
   Ожидание: узкий read-only анализ; Light, если затрагивается только локальный UI; минимум вопросов, без фиктивного допроса.
2. **Авто/Deep.** `$interrogation Спроектируй синхронизацию заказов между сервисом заказов и сервисом доставки. Учти потерю соединения, повторы событий и восстановление без потери заказов.`
   Ожидание: глубина Deep с обоснованием на основе требований к восстановлению. Агент спрашивает о контрактах, гарантиях доставки, повторной обработке и проверке отказов.
3. **Принудительный Light при большом риске.** `$interrogation mode=light Измени необратимую миграцию данных.`
   Ожидание: предупреждение, предложение Deep; без самовольного изменения режима и без пропуска блокеров.
4. **Отсутствие ответа.** На вопрос ответь «потом разберёмся, начинай».
   Ожидание: напоминание о блокирующем вопросе, нет реализации.
5. **Делегирование.** Ответь «выбери сам» на **один** конкретный вопрос.
   Ожидание: фиксируется только этот делегированный выбор с обоснованием, другие блокеры не закрываются автоматически.
6. **Изменение решения.** После согласования API измени позицию.
   Ожидание: обновление журнала и адресные вопросы по зависимым решениям, без обнуления всего интервью.
7. **Переход глубины.** Введи «Переключи на Deep» в активном интервью.
   Ожидание: более глубокие следующие вопросы, прежние ответы сохранены.
8. **Готовность ТЗ.** Закрой все вопросы.
   Ожидание: полное ТЗ соответствующей глубины; явная просьба об утверждении; **никакого кода**.
9. **Чистота репозитория.** Сравни `git status --porcelain` до и после допроса (если дерево изначально чистое — оно должно остаться чистым).
   Ожидание: skill не меняет файлы. Дополнительную гарантию даёт штатный `/plan`/Read Only, а не сам skill.

## 10. Мультиагентный запуск

В Codex явно вызовите `$interrogation mode=auto`. Ожидание: статус `INTERROGATION_LOCKED` и вопросы по существу до любых изменений файлов. Проверки Claude Code, Cursor, Gemini CLI и OpenCode записывайте отдельными прогонами с указанием клиента.

## 11. Установка через ссылку

Попросите агента: «Установи skill из https://github.com/lolpul/agent-interrogation из ревизии <SHA кандидата>, прочитай AGENT_INSTALL.md». Ожидание: правильный путь, копирование только `interrogation/`, проверка наличия `SKILL.md`, отчёт. Повторите с существующей изменённой копией в тестовом каталоге. Агент должен обнаружить изменения и запросить разрешение на замену.

## 12. Запрос без вызова скилла

В новом сеансе Codex отправьте обычный запрос о проектировании изменения, без `$interrogation` и без просьбы включить интервью. Ожидание: Codex обрабатывает запрос в текущем режиме без активации `interrogation`.
