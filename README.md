# Interrogation Mode — Universal Agent Skill

**Адаптивное интервью по требованиям до написания кода — для Codex, Claude Code, Cursor, Gemini CLI и OpenCode.**

[English](README.en.md) · [Установка агентом](AGENT_INSTALL.md) · [Ручная установка](INSTALL.md) · [Сценарии проверки](TEST_SCENARIOS.md) · [История изменений](CHANGELOG.md)


## Зачем это нужно

Обычно запрос «сделай интеграцию», «добавь модуль» или «переделай архитектуру» содержит не все необходимые детали. Кодовый агент может подобрать разумные значения по умолчанию, но при сложной задаче ошибка в предположении приводит к лишним итерациям: переписыванию API, изменению схем данных, повторной реализации сценариев и исправлению регрессий.

**`interrogation` предлагает сначала разобраться в задаче:** прочитать относящийся к ней код, выяснить недостающие требования, обнаружить противоречия, согласовать ключевые решения, составить проверяемое ТЗ и **отдельно запросить разрешение начать реализацию**.

Цель — уменьшить число дорогих переделок и не тратить время на избыточные вопросы там, где задача простая. Экономия времени и токенов **не гарантируется** и зависит от проекта.

### Что делает skill

1. Устанавливает состояние `INTERROGATION_LOCKED` — по инструкции не допускает написание кода до утверждения ТЗ.
2. Изучает релевантные части репозитория в режиме чтения; не спрашивает то, что можно выяснить из файлов.
3. Оценивает масштаб, неопределённость, риск и количество интеграций (S/U/R/I).
4. Выбирает глубину интервью **Light / Standard / Deep** либо использует явно заданную пользователем.
5. Задаёт вопросы порциями, объясняет варианты, ведёт краткий журнал согласованных и открытых решений.
6. При обнаружении нового риска корректирует глубину, не начиная допрос заново.
7. Формирует ТЗ с критериями приёмки и ожидает явного утверждения.

**Не является системной блокировкой записи.** `SKILL.md` — инструкция для модели, а не средство принудительного контроля доступа. Для дополнительной защиты используйте встроенное планирование или read-only режим, если он предусмотрен конкретным агентом. Возможность записи зависит от его настроек. Даже с включённым skill проверяйте действия агента.

## Установить с помощью своего ИИ-агента (рекомендуется)

Не нужно вручную искать каталоги skills. **Скопируйте эту строку в чат Codex, Claude Code, Cursor, Gemini CLI или OpenCode**:

```text
Установи skill Interrogation Mode из https://github.com/lolpul/agent-interrogation. Прочитай AGENT_INSTALL.md, определи свой агент, установи skill глобально, не затрагивай другие skills, проверь установку и скажи, как запустить.
```

Агент может потребовать доступ к GitHub и подтверждение записи файлов. **Одна только ссылка без просьбы установить skill не всегда достаточна**: агент может решить, что нужно просто открыть репозиторий. Порядок установки для самих агентов находится в [AGENT_INSTALL.md](AGENT_INSTALL.md).

### Поддерживаемые агенты

| Агент | Установка | Запуск |
| --- | --- | --- |
| **Codex** | `~/.agents/skills` или существующий `~/.codex/skills` | `$interrogation` |
| **Claude Code** | `~/.claude/skills` | `/interrogation` |
| **Cursor** | `~/.cursor/skills` | `/interrogation` в Agent chat |
| **Gemini CLI** | `~/.gemini/skills` или `gemini skills install` | Явная просьба активировать skill |
| **OpenCode** | `~/.config/opencode/skills` | `@interrogation` |

`mode=light|standard|deep|auto` работает на уровне инструкции в `SKILL.md`; это не встроенный параметр перечисленных агентов. На других агентах возможна ручная адаптация.

## Ручная установка (пример: Codex)

Скачайте [исходный код](https://github.com/lolpul/agent-interrogation/archive/refs/heads/main.zip) или клонируйте репозиторий. Перенести требуется **только каталог `interrogation`**, содержащий `SKILL.md` и `agents/openai.yaml`.

**Windows PowerShell (глобально, рекомендованный каталог):**

```powershell
New-Item -ItemType Directory -Force "$HOME\.agents\skills" | Out-Null
Copy-Item -Recurse -Force ".\interrogation" "$HOME\.agents\skills\"
```

**Windows (альтернативный каталог, если ваш Codex уже использует `.codex\skills`):**

```powershell
New-Item -ItemType Directory -Force "$HOME\.codex\skills" | Out-Null
Copy-Item -Recurse -Force ".\interrogation" "$HOME\.codex\skills\"
```

**Linux / macOS (глобально):**

```bash
mkdir -p ~/.agents/skills
cp -R ./interrogation ~/.agents/skills/
```

Чтобы skill действовал **только в одном проекте**, перенесите `interrogation` в `<проект>/.agents/skills/`. Для обновления замените существующий каталог, предварительно сделав резервную копию своих изменений. **Не устанавливайте одновременно две копии с одинаковым именем**, если они могут конфликтовать по приоритету.

Полные инструкции, установка из ZIP, диагностика и примеры — в [INSTALL.md](INSTALL.md).

После установки начните **новую сессию Codex** и вызовите skill по имени `$interrogation`. Codex можно дополнительно перевести в `/plan` до запуска интервью.

## Использование (примеры для Codex)

В сообщении Codex:

```text
$interrogation Спроектируй добавление настроек отображения сетки.
```

По умолчанию используется `mode=auto`. Можно явно указать глубину:

```text
$interrogation mode=light Добавь одну настройку в существующий UI.
$interrogation mode=standard Согласуй API двух сервисов.
$interrogation mode=deep Спроектируй критичную интеграцию с отказоустойчивостью.
```

`mode=...` — **текстовое соглашение нашего skill**, а не встроенный флаг CLI Codex. В ходе интервью можно написать «Переключи на Deep»; уже согласованные решения должны сохраниться в текущем чате.

### Режимы

| Глубина | Когда применять | Как проходит интервью | Что получается |
| --- | --- | --- | --- |
| **Light** | Локальная функция, ясный scope | Обычно 2–5 важных вопросов, без искусственной квоты | Короткое ТЗ и критерии приёмки |
| **Standard** | Несколько модулей, API, поведение системы | Вопросы по 2–4 за раунд до закрытия блокеров | ТЗ с решениями, ошибками, тестами и планом |
| **Deep** | Сложные интеграции, критичные изменения | Глубокий разбор альтернатив, инвариантов, отказов, совместимости и рисков | Детальная спецификация, стратегия верификации и риски |

**Важно:** количество вопросов — ориентир, а не основание закончить допрос. Во всех режимах критичные неизвестные должны быть закрыты. При явно заданном режиме skill не повышает его без согласия пользователя, но предупреждает о недостаточной глубине.

### Автоматический выбор

По релевантному контексту Codex оценивает `S` (scope), `U` (uncertainty), `R` (risk), `I` (integrations), каждый от 0 до 2. Сумма 0–2 соответствует Light, 3–5 — Standard, 6–8 — Deep. Правила минимального уровня применяются при значимых рисках, например миграции данных или критичной безопасности. Это эвристика для организации диалога, а не метрика надёжности.

### Этапы работы

```text
$interrogation
     │
     ▼
Read-only анализ проекта
     │
     ▼
Выбор Light / Standard / Deep
     │
     ▼
Вопросы → ответы → уточнение → журнал решений
     │
     ▼
Все блокирующие вопросы закрыты?
     ├─ Нет → следующий раунд интервью
     └─ Да
          ▼
     Финальное ТЗ и критерии приёмки
          │
          ▼
     Явное утверждение пользователем
          │
          ▼
     Выход из /plan / Read Only при необходимости
          │
          ▼
     Отдельный этап реализации
```

## Чем отличается от `/plan`

**`/plan`** — штатный режим Codex для проектирования пути реализации. **`$interrogation`** — пользовательский сценарий, который делает акцент на **выяснении и согласовании требований** до составления окончательного ТЗ. Их можно использовать вместе: сначала переключиться в `/plan`, затем вызвать `$interrogation`. Skill не заменяет возможности и ограничения штатного режима Codex.

## Пример диалога

**Пользователь:** `$interrogation mode=auto Добавь экспорт отчёта из панели управления.`

**Codex:** «Статус: `INTERROGATION_LOCKED`. После чтения модуля экспорта выбрана глубина Standard: экспорт затрагивает API и формат данных. Нужно согласовать: (1) CSV или XLSX? (2) какие поля и фильтры? (3) как обрабатывать ошибки?»

**Пользователь:** «CSV, текущие фильтры, ошибки показывать в интерфейсе».

**Codex:** «Согласовано ... Остался вопрос: нужны ли ограничения по объёму экспорта?»

**…После закрытия всех блокеров:** Codex показывает ТЗ и просит: «Утверждаю ТЗ, приступай к реализации».

Это **иллюстрация ожидаемого поведения**, а не результат автоматического теста.

## Ограничения

- Skill — промпт-инструкция; никакой жёсткой гарантии отсутствия записей или правильности решений не даёт.
- Работа с файлами и доступные режимы зависят от версии и окружения Codex.
- Журнал решений существует **в контексте текущей беседы**; между разными чатами переносите ТЗ/сводку вручную.
- При плохо сформулированной задаче интервью может быть длинным; при простой задаче он может оказаться дороже прямой реализации.
- `mode=...` не является официальным параметром Codex.
